# KIF Web Push Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver opt-in player notifications for new team posts and incoming leader messages, with unread app badges and a verified player guide.

**Architecture:** Add authenticated player preferences/subscriptions and a transactional outbox in existing Supabase. A service worker displays encrypted Web Push notifications; an authenticated backend dispatcher handles delivery and retries. Existing content remains the source of truth.

**Tech Stack:** Vanilla JS, Node test runner, PostgreSQL RLS, Supabase Edge Functions, Web Push/VAPID, pg_net, pg_cron, Vault, Word/PDF.

**Spec:** docs/superpowers/specs/2026-10-07-web-push-design.md

## Global Constraints

- Player recipients only; active account, current same-team access, no sender self-notification.
- New posts and messages only; no backlog on activation and no push on post edit.
- Generic notification copy: “Nytt laginlägg i KIF” / “Nytt meddelande i KIF”. No message body on the lock screen.
- Profile → Notiser → Aktivera notiser; independent Laginlägg and Meddelanden switches; own-device test and disable controls.
- No offline cache of authenticated content; no silent pushes solely to update badges.
- Roster IDs and profile IDs must remain distinct. Server computes unread count.
- Multiple devices; logout detaches this device and clears its local badge.
- Code baseline: backup/kif-before-push-2026-10-07 at 57189d2c3a4edba47567bb9647b5d494e2553553.
- Work on an isolated branch/worktree. Preserve existing application rows; additive migration only. Never commit secrets or database exports.
- Backend remains disabled for player delivery until automated validation and Henric's phone trial succeed. General publication/merge follows the existing user-authorized workflow.

## Review Focus

- Account switch on a shared phone must not transfer the old user's subscription to the new user without explicit activation (Task 3).
- A slow queued job after a player's team/role changes must be skipped (Task 2).
- A notification clicked while logged out must retain its destination and revalidate access after login (Task 4).
- Concurrent worker retries after an interrupted request must not process one job at the same time (Task 2).
- A revoked permission or unsupported browser must show usable recovery instructions without breaking profile/chat (Task 3).

### Task 1: Durable notification data and safe rollback

**Files:** new CLI-generated supabase/migrations/*_web_push.sql; supabase/tests/web_push.sql; docs/operations/web-push.md.

**Interfaces:**
- push_preferences(profile_id, posts_enabled, messages_enabled, enabled_at).
- push_subscriptions(id, profile_id, endpoint, p256dh, auth, enabled, created_at).
- push_notifications(id, profile_id, kind, source_id, team, created_at, read_at), unique recipient/kind/source.
- push_delivery_jobs(id, notification_id, subscription_id, state, attempts, available_at, lease_until, lease_token), unique notification/subscription.
- RPC register_push_subscription(endpoint text, p256dh text, auth text) → UUID; disable_push_subscription(endpoint text) → void. Authenticate active player, enforce endpoint/key size and provider validation.
- RPC set_push_preferences(posts boolean, messages boolean) → own preference row; get_push_status() → {posts_enabled, messages_enabled, unread_count, public_key, delivery_enabled}.
- RPC mark_push_post_read(post_id uuid) → own unread_count, validating present post/team access.
- Service-only RPC configure_push_keys(public_key text, private_key text, contact text) → void stores values in Vault. Service-only get_push_worker_config() exposes config only to service_role. No secret in browser/API grants.

- [ ] Write SQL assertions: anonymous denied; another player cannot read/write preferences, subscriptions or notifications; leader cannot assume player identity; invalid provider/private destination rejected; duplicate registration safe; no old notification backfill; disabled preference excluded from badge.
- [ ] Run SQL test against baseline in a rolled-back transaction and record expected missing-function/table failure.
- [ ] Create migration with Supabase CLI. Implement RLS, explicit grants and exact RPCs, activation timestamps and subscription ownership. Do not alter/delete original posts, messages, reads or profiles.
- [ ] Document rollback: disable dispatch, unschedule only the new job, remove only new triggers, revert frontend to backup branch; retain new notification data pending a deliberate cleanup. Preserve original tables.
- [ ] Run migration plus tests transactionally; inspect advisors for introduced problems; commit tested migration and rollback instructions before application.

### Task 2: Transactional events and authenticated push delivery

**Files:** same migration; supabase/functions/kif-push/index.ts and push-policy.ts; tests/web-push-delivery.test.js; SQL tests.

**Interfaces:**
- claim_push_jobs(batch_size integer) → leased jobs with lease_token. service_role only, SKIP LOCKED, batch ≤ 100, lease 2 minutes.
- finish_push_job(job_id uuid, token uuid, outcome text, http_status integer) → void; token must match lease.
- get_push_delivery(job_id uuid, token uuid) → eligible subscription + generic content + unread_count, or null. Revalidate active player, linked roster account, team, preferences, unread status and source existence.
- kif-push HTTP POST: exact worker bearer secret from Vault; OPTIONS not an authorization bypass. verify_jwt=false only with implemented worker-token authentication. Test request routes require separate valid user JWT and own active player identity.
- Notification payload {id, kind, source_id, title, body, url, unread_count}; url is a fixed same-origin app route, never source-supplied.

- [ ] Write tests: one inserted post reaches same-team opted-in players only; one leader message reaches its linked active player only; message read marks notification read; edit is ignored; no backlog; team changes skip queued jobs; lease concurrency safe; mismatched token denied.
- [ ] Run failing tests before implementation.
- [ ] Add triggers that atomically enqueue events without issuing network calls in the publication transaction. Worker wakes asynchronously; minute cron supplies retries. Worker's failure must not roll back source content.
- [ ] Pin a maintained Web Push dependency after official compatibility/security verification. Generate VAPID keys without printing private values; use service-only configuration interface. Validate public HTTPS push hosts and reject redirects; impose request timeout 10 seconds.
- [ ] Retry transient failures at 1, 5 and 30 minutes; at most 4 attempts. Disable subscription on 404/410. Use stable notification-tag from notification ID. Keep payload/logs free of private message text and keys.
- [ ] Test blocked auth, internal/private endpoints, stale subscriptions, network timeout and interrupted lease recovery. Run SQL rollback fixtures and dispatcher tests; commit.
